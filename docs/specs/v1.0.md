# tv-live v1.0 规格

- 状态：2026-10-28 开始执行
- 目标设备：TCL L32F3800A，Android 4.4.3 / API 19，MT5882，566 MB RAM，1920×1080 @ 240dpi
- 同时保持普通 Android TV（API 19+）可安装；不写死 TCL 路径、不 root、不默认改桌面
- 设计参考：`docs/design/tv-ui.html`（6 个状态：首次 / 列表 / 全屏 / 换台 / 菜单 / 返回）
- 包名：`me.qnnp.tvlive`；App 名「直播」；版本 `0.1.0`

## 1. 目标与范围

做一个极简、遥控器优先的直播 App：用户自备 m3u/m3u8 源，左列表 + 右预览，选中即预览，OK 全屏；全屏只有画面，整点/半点前后各 30 秒显示带秒的时间；手机浏览器负责首次设置源；收藏、上次频道、开机自启。

v1.0 包含：

- 多源（≤8 个 URL/文件）合并、源管理、分组、编号、同频道多 URL 变体
- ExoPlayer 2.18.1 播放 + MediaPlayer 兜底 + 错误切源
- TV UI（首次设置 / 列表+预览 / 全屏 / 换台 OSD / 菜单 / 退出提示）
- 收藏、上次频道、数字键/CH+/−/长按 OK/MENU
- 手机 HTTP 设置页（v1.0 只做源导入）、二维码、PIN
- 开机自启（标准 receiver，默认关）
- 设置页：源管理、开机自启、关于

v1.1 暂缓：完整手机遥控（频道列表、搜索、音量、全屏、收藏）。

不做：EPG、回看、录制、投屏、云同步、账号、root、系统分区改动、后台常驻服务。

## 2. 设备与环境事实

- API 19 / Dalvik，64K 方法数限制；566 MB RAM；1920×1080 @ 240dpi。
- `/sdcard` 未挂载，`/storage/emulated/0` 不存在；App 只用 `getFilesDir()`（`/data/data/me.qnnp.tvlive/files`）。
- TLS 只到 1.0，`https://` 源在本机大概率失败；通用版保留 https，失败时提示 TLS 不支持并切下一条。
- TCL PackageParser 对带 `android:banner` 的 APK 会崩；本 App 绝不声明 `android:banner`。
- `pm` 以 shell 跑会被 OOM；App 不需要 root/pm。
- 电视/模拟器：真实设备地址用本地环境变量 `TV_LIVE_ADB` 或仓外 notes 保存，不入库；模拟器 `emulator-5554`。
- 设备 notes 只放仓外（路径由本地环境决定），不入库。

## 3. 产品口径（硬约束）

1. 初始源为空：不预置 m3u、不自动扫描 `/data/media/0`、`/data/local/tmp`、`/sdcard`。
2. 首启显示手机设置地址 + 6 位 PIN + 二维码；手机扫码/打开地址，粘贴 m3u/m3u8 URL 或上传文件；App 校验后存 `getFilesDir()/sources/<id>.m3u` + `sources.json`，自动进列表；最多 8 个源，合并显示。
3. 电视没有文件选择器；手机设置页是主路径；电视上保留「在本机输入地址」；通用设备可用 SAF。
4. 有源且有上次频道：启动直接全屏上次台，不闪启动 OSD；无源/全部失效：停在首次设置或列表。
5. 全屏只有画面，无常驻台标/频道名/时间/水印/状态栏。
6. 时钟角标：仅全屏，整点/半点前后各 30 秒（共 1 分钟，`:59:30–:00:30`、`:29:30–:30:30`），右上角 `HH:mm:ss`，每秒刷新，24 小时制；其余时间隐藏；菜单打开时隐藏。
7. 换台/按 OK 才出 2.5 秒 OSD；菜单/错误/退出提示都是临时 UI。
8. 列表：左侧竖排分组栏（收藏 / 央视 / 卫视 / 地方 / 港澳台 / 其他）+ 频道列表 + 右侧预览；组内保持源顺序；号码 = 全局显示顺序；焦点移动不换台，数字/CH 移焦点，OK 两段（先预览、再全屏）；→ 打开焦点台菜单；「其他」按源组二级分组。
9. 列表不加载台标（省内存）；收藏后行尾星标 + 收藏组置顶。
10. 收藏：列表/全屏长按 OK 或 MENU → 菜单第一项 收藏/取消收藏；若遥控有红键/书签键，映射 `PROG_RED`/`BOOKMARK` 一键切换。
11. 退出：全屏 Back → 导航隐藏（画面）；导航显示时 Back 收起导航；导航隐藏时第一次 Back 只显示 2 秒「再按一次返回退出」，2 秒内再按才退出；菜单 Back/LEFT 只关菜单；Home 只后台；菜单「退出」明确退出。
12. 开机自启：`BOOT_COMPLETED` receiver + 设置开关，默认关；`PackageManager.setComponentEnabledSetting` 启停自己的 receiver；不 root。
13. 默认桌面：v1.0 不做。TCL 4.4 的 PackageVerifier 拒绝任何第三方 HOME 声明（`activity-alias` 与普通 activity 均 `INSTALL_FAILED_VERIFICATION_FAILURE`），主 APK 不得声明 HOME；保留「返回系统桌面」显式拉起 bama（`com.tcl.bama.launcher/.Launcher`），缺失时回系统 Home 选择器。通用设备的默认桌面留 v1.1 独立包。
14. 通用：不 root、不写 `/system`、不默认替换桌面、不申请存储权限、不依赖 `/sdcard`。
15. 手机 HTTP 设置页 v1.0 只做源导入；完整遥控 v1.1。

## 4. 架构

单 Activity（`MainActivity`，landscape，`configChanges`），framework views，Java 8，无 Kotlin、无 Compose、无 AndroidX UI。

```
data/      PlaylistModel（Channel/Variant/Playlist/Group）
           PlaylistParser
           ChannelSet（分组/编号/变体合并）
           SourceStore（sources.json/缓存/迁移）/ ChannelMerger（多源合并）
           PlaylistRepository（getFilesDir / 读写 / 元数据）
player/    PlaybackController（状态机/切台/错误策略）
           PlaybackEngine（接口）
           ExoEngine（ExoPlayer 2.18.1 core+hls）
           MediaPlayerEngine（兜底）
           PlaybackError（错误分类）
ui/        MainActivity
           ChannelListAdapter / ChannelRowView
           SetupView（首启：URL/PIN/二维码/本机输入）
           OsdView（换台/错误）
           MenuView（右侧菜单）
           SettingsView（源/自启/关于）
           ClockView（全屏时间角标）
control/   ControlServer（NanoHTTPD 2.3.1）
           SourceApi（source/url、source/upload）
           TokenStore（6 位 PIN/失败退避）
           WebAssets（assets/control/index.html）
           QrCode（ZXing core 3.5.3，生成二维码 Bitmap）
prefs/     AppPrefs（收藏、上次频道、自启、源标签）
boot/      BootReceiver；HomeController（返回系统桌面）
```

- 线程：解析/网络/文件在后台；UI 和播放器在 main；HTTP 在固定 3 线程；状态用不可变快照；不阻塞 main。
- 生命周期：单 Activity；`onStop` 释放播放器/停止 HTTP；`onStart` 恢复上次频道；保持屏幕常亮；音频焦点；不做后台播放。
- 单 `SurfaceView`：预览/全屏只改布局，不重建播放器，不 reparent。

## 5. 解析 / 分组 / 存储

### 5.1 解析

- 只接受 m3u/m3u8 频道表；Xtream 用 `get.php?...type=m3u_plus&output=ts` 的 m3u URL，不做专有 API。
- 编码：UTF-8 BOM 检测；UTF-8 严格解码失败转 GB18030；再失败报错。
- 行：`#EXTM3U`、`#EXTINF:<duration> attrs,title`、`#EXTGRP:<group>`、`#EXTVLCOPT:http-user-agent=...`、`#EXTVLCOPT:http-referrer=...`；`#KODIPROP:` 忽略；`#EXT-X-` 视为 HLS 媒体列表，不是频道表，报错。
- 分组优先级：每条 `#EXTINF` 的 `group-title` 非空时优先；否则用最近一次 `#EXTGRP`（粘性）；两者都空再由 `ChannelSet` 按名称分类。
- attrs：`tvg-id`、`tvg-name`、`tvg-logo`、`group-title`；未知忽略。`tvg-chno` 不用于编号。
- URL 行：`http://` / `https://`；其他跳过；相对 URL 在源为 http 时按源 URL 解析，否则跳过。
- Channel：`id`（tvg-id 优先，否则 group|normalizedName）、name、group、variants、logoUrl（解析但不显示）、number（后续分配）。
- Variant：url + userAgent + referer；同频道多 URL 合并：同 tvg-id 优先，其次同 group + 规范化名称；保持源顺序。
- tvg-id 变体 key 去掉 `@` 后缀（`CCTV1.cn@SD`/`@HD` → `CCTV1.cn`），同频道不同质量合并为 variants；显示名清理质量/备注后缀，分类用原名；`group-title`/名称 `更新时间` 的 metadata 不作为频道。
- 名称：trim、全角空格归一、去空；无名称用 URL 末段。
- 结果：channels、groups、skippedHttps/unsupported、error；空文件/无频道报错。
- https 不全局剔除；播放失败时按 TLS 错误提示。

### 5.2 分组 / 编号

- group-title 有意义时用它；`General`/`China`/`中国`/`默认`/`未分类`/空 → 按名称分类。
- 分类（名称优先）：含 CCTV/央视 → 央视；含 卫视 → 卫视；含 地方/城市 → 地方；含 港澳台/香港/澳门/台湾 → 港澳台；其余按 group-title 别名（央视频道/CCTV → 央视；卫视频道 → 卫视；地方频道 → 地方；港澳台/台湾香港澳门 → 港澳台），都不匹配 → 其他。
- 顺序：收藏（UI 虚拟组）/ 央视 / 卫视 / 地方 / 港澳台 / 其他；源里其他组一律归其他，不再保留 Religious/News/电影频道 等类别 tab。
- 组内保持源顺序；全局编号 1..N 按最终显示顺序；收藏不改编号。
- 数字键 2 秒缓冲，输入超界提示「无此频道」；CH+/− 换台。

### 5.3 存储

- 持久化：`getFilesDir()/sources.json`（源元数据/顺序/启用）+ `getFilesDir()/sources/<id>.m3u`（每源缓存）；临时文件同目录，写完 rename；不写外部存储。旧 `playlist.m3u` 迁移为第一个源。
- 不申请 `READ/WRITE_EXTERNAL_STORAGE`；不硬编码 `/data/media/0`、`/sdcard`、`/data/local/tmp`。
- 源导入：URL（http/https，API 19 https 失败提示）、手机上传 raw bytes、SAF（`ACTION_OPEN_DOCUMENT`，无选择器时提示）、本机 URL 输入；限制 5MB；校验 `#EXTM3U`/`#EXTINF`。
- 源标签：URL host 或文件名；元数据 mtime/size/channelCount；设置页显示/更换/重新加载/清除。
- 源 sidecar：`getFilesDir()/playlist.meta`（Properties/JSON）保存 `sourceType`（url/upload/saf/adb）、`sourceUrl`、`displayName`、`importedAt`；`SourceInfo.label` 优先 displayName/host，缺失回退文件名；有 `sourceUrl` 时作为解析 baseUrl，支持相对 URL。批次 1 只做文件；sidecar 在批次 3 接入。
- 首次源为空：不自动导入；只显示设置页。

## 6. 播放

- ExoPlayer 2.18.1：`exoplayer-core` + `exoplayer-hls`；不用 `exoplayer-ui`；`SurfaceView` + `Player.Listener`。
- `DefaultHttpDataSource`：UA/Referer、connect/read timeout 8s；不跨协议重定向；错误分类。
- 渲染：`DefaultRenderersFactory.setEnableDecoderFallback(true)`；MediaCodec 硬解优先；prepare 后查 `Tracks`/`MediaCodecUtil`，HEVC/AC3 无解码器 → 明确提示并切变体；2.x 不做软件解码。
- 清晰度上限（1.0.43 → 1.0.45）：不再全局写死 1080p。`VideoProfile` 在 API 21+ 用 `MediaCodecList`/`VideoCapabilities` 查是否支持 3840×2160（HEVC/AVC），支持才放开 4K；API 19（TCL L32F3800A / MT5507）没有 VideoCapabilities，固定 1920×1080。`DefaultTrackSelector` 按 profile 设置 `maxVideoSize`。原因：TCL 上 4K HEVC 会让厂商 `MediaCodec.flush()` 永久阻塞，随后所有频道都起不来，只能重启电视（2026-10-29 实机）。
- 起播预探测（1.0.45）：`StreamProbe` 按成本从低到高，取第一个有效结果：
  1. HLS master playlist 的 `RESOLUTION`/`CODECS`；
  2. HLS media playlist 的**最新分片 + 最老分片**：下载前几 MB，先 `MediaExtractor`，再 Exo `TsExtractor`/`FragmentedMp4Extractor`，不创建厂商解码器；
  3. 非 HLS/解析失败：抓 URL 头部走同样 Extractor；
  4. 全部失败：`UNKNOWN`，普通 URL 放行（避免 404/301/TLS 误杀正常频道）；只有已知 4K URL 或实机卡死过的源做保守跳过。
  - 结果按 URL 缓存（内存成功 10 分钟，UNKNOWN 1 分钟）；成功 Format 另存持久化白名单：URL + 设备 profile 为键，7 天、最多 300 条 LRU；命中直接跳过探测（日志 method=whitelist）；首帧成功后也会按实际选中 Format 写入（method=playback），所以预探测失败但能正常播放的 URL 下次也会命中；每次成功播放续期，常用 URL 实际不过期；
  - 播放失败/起播超时会 invalidate 对应 URL，下次重新探测；普通频道 UNKNOWN 不写白名单；
  - `UNSUPPORTED` 不换 MediaPlayer，直接下一个 variant/频道；
  - 1.0.44 的频道名屏蔽已移除，改为 `bestv.cn/148/3/` 等**实机卡死 URL 的负缓存**（不是按频道名）。
- 起播看门狗（1.0.43）：PREPARING/BUFFERING 超过 15 秒未进入 PLAYING，先销毁并重建引擎、重试当前台一次；再超时按卡住处理并交给自动跳台。
- 视频帧看门狗（1.0.51）：`VideoFrameMetadataListener` 每次渲染更新 `lastVideoFrameAtMs`；PLAYING 但 12 秒无新帧（position 可能仍在走）→ 重建重试一次，再失败自动跳台。`checkStall` 的 `stallRetryDone` 只在换台/用户操作时重置，避免“重试后走一小段又卡住”无限循环。探针只能抽样，不能保证直播流中途不变 4K；真正的 renderer 层 Format 上限仍是后续项。
- MediaPlayer 兜底：仅 decoder/container 错误；网络/HTTP 错误直接切变体；`UNSUPPORTED` 不换引擎直接切变体；同一时刻只保留一个活跃解码器。
- 变体：同频道多 URL 依次试；全失败后，全屏 3 秒自动下一台（任意键取消）；列表预览失败只提示不跳台；连续 5 台失败停手。
- 卡顿：播放位置 10 秒不前进 → 视为失效；错误 OSD 区分网络/403/解码器/格式/TLS。
- 缓冲：`DefaultLoadControl` 小缓冲（约 min 3s / max 12s / playback 1s）；优先稳，不追求低延迟；避免 512MB OOM。
- 切台：选中 300ms 防抖；取消上一个 prepare；复用 player；`stop`/`clearMediaItems`；失败不崩。
- 预览/全屏共用同一 player；全屏只改容器 LayoutParams；不重建 Surface。
- `onStop` release；`onStart` 恢复上次频道；音频焦点；`FLAG_KEEP_SCREEN_ON`。
- 启动：有上次台 → 直接全屏播放，无 OSD；失败 → 列表/设置。

## 7. UI / 交互

设计参考 `docs/design/tv-ui.html`；实际用 dp/sp，不用 cqw。视觉 token：

- ink `#070C0D`，surface `#0B1214`，text `#E8EDEA`，muted `#7E908B`，tally `#E36A4A`，hairline `rgba(230,236,232,.07)`。
- 无纯黑大底、无卡片堆叠、无渐变装饰；唯一强色 tally，只用于选中/收藏/焦点/当前台号。
- 列表不显示台标；无永久 OSD；全屏只有视频 + 半时钟。

布局：

- 根 `FrameLayout`；导航默认隐藏，宽 44%，内部组栏 24% + 频道列表 76%。批次 8 起导航搬到 **root 层**（`NavView`，位于 TvLayout 之后、浮层之前；显示时 `bringChildToFront` 压住 TCL `SurfaceView` 合成层），**覆盖**在全宽视频上而不是挤压视频；收起后 `GONE`。视频容器始终全宽，画面在容器内按 16:9 等比 fit 并居中，黑边用预览底色（1920×1080 正好铺满）。只改 `LayoutParams`，`SurfaceView` 不重建、不重绑播放器。
- 设置页 / 首启页同样在 root 层；设置页为全屏 90% 黑半透明覆盖层，视频保持全宽继续播放，内容居中（窄屏单列全宽），不缩视频。
- 导航弹出 220ms 滑入 + 淡入，底色 90% 不透明 + 右缘 24dp 渐变；不做实时 blur；收起后 `GONE`，不拦截按键。
- 1080p/720p 都要不裁字；列表可滚动且末项完整；行高/字号用 dp/sp + 资源限定，避免 720p 溢出。
- 选中行 full-bleed 背景 + 左侧 tally 条 + 台号 accent；收藏星在行尾；播放行行尾弱 `●`；分组 active 左侧条；焦点行名称超长跑马灯，非焦点省略。焦点样式同一时刻只属于一个区域：焦点在组栏时组项亮底色 + 亮组名，列表行不画焦点（仅保留播放 `●`）。
- 导航显示（NAV_SHOWN）：焦点 ≠ 播放；上下/数字/CH 只移焦点；列表上下在组内循环（首台上→末台、末台下→首台）；左右在组栏与列表间移动；OK 两段；→ 打开焦点台菜单；Back 收起导航；8s 无操作自动收起。
- 导航隐藏（NAV_HIDDEN，默认）：上下/CH/数字直接换台；左右调音量（自绘 2s 音量条）；OK/Back/长按 OK 弹出导航；播放失败 3s 自动跳。
- 导航显示（NAV_SHOWN）：Back 第一次提示「再按一次返回退出」，2 秒内再按退出，不收起导航；导航 8s 无操作自动收起。
- 预览：只由 OK/全屏/恢复/隐藏态换台改变；信息在视频下方，不叠在画面；预览失败不自动跳。
- 全屏：无常驻元素；换台/OK 出 2.5s OSD；长按 OK/MENU 出右侧菜单；Back → 导航隐藏；左右调音量、上下换台、数字直选；连续 5 个失败停止自动跳并回列表。
- 时钟：全屏播放时，距最近 :00/:30 ≤30s 显示 `HH:mm:ss`，每秒刷新；右上角；菜单打开时隐藏。
- OSD：左下角，台号/名称/分组（分辨率后续补）；2.5s 自动消失；错误 OSD 说明原因。
- 加载角标：预览/全屏右下角小提示「加载中…」；起播/切台 500ms 无首帧才出现；首帧/错误/菜单打开时隐藏；不挡 OSD/时钟/菜单。
- 主菜单（MENU，任意状态，右侧浮层）：重新加载列表、设置、退出。频道操作列常驻导航内、列表右侧（作用于焦点台）：收藏/取消、切换线路、频道信息、全屏播放；列表 `→` 进入，`←` 返回。Back 在操作列里只收起操作列、保留导航与频道焦点；主菜单 Back/LEFT 关闭主菜单。
- 分组切换焦点：组内含播放台则落在播放台，否则该组第一台。
- 设置：源列表（名称/台数/状态/启用/重载/改名/排序/删除）、开机自启开关、返回系统桌面、关于（版本/IP/端口/PIN/诊断）；添加源在手机页。
- 首次设置：不预置源；显示手机地址 + 6 位 PIN + 二维码 + 「在本机输入地址」；手机导入后自动进列表；无 WiFi 提示先连 WiFi。
- 退出：全屏 Back → 导航隐藏；导航隐藏态 Back 弹出导航；导航显示态 Back 第一次提示「再按一次返回退出」，2 秒内再按退出；菜单 Back/LEFT 只关菜单。
- 启动/恢复：有上次台直接全屏；不闪列表再跳；无源停设置页。

## 8. 手机 HTTP 设置页（v1.0 最小）

- 服务在 TV App 内：自研最小 HTTP/1.1（ServerSocket + 每连接一线程 + 10s 超时）；`Connection: close`；端口 18088 → 18089 → …；显示实际端口。
- 启动：首启/设置页/无源时启动；Activity 可见时可控；`onDestroy` 停止；不做后台常驻。
- 页面：`assets/control/index.html` 单个内联 CSS/JS；手机优先；深色；显示当前源状态 + URL 输入 + 文件上传 + 导入结果。
- 鉴权：6 位 PIN，`X-TvLive-Token` 头；失败 5 次退避 30s；页面 localStorage 存 token；同源不开 CORS。
- 二维码：ZXing core 3.5.3 生成；内容 `http://<ip>:<port>/#t=<pin>`；IP/端口变化重生成；只首启/设置页显示；手机扫码自动带 PIN。
- 接口（v1.0）：
  - `GET /` 页面
  - `GET /api/ping` → `{ok, version, tokenRequired}`
  - `GET /api/state` → 源状态/频道数/当前台/播放状态
  - `POST /api/source/url` `{url}` → 拉取/校验/保存/解析
  - `POST /api/source/upload` raw body（`X-Filename`）→ 保存/解析
  - `POST /api/source/reload` / `POST /api/source/clear`
- 源导入：5MB 限制；校验 m3u；编码检测；失败返回中文原因；成功后 TV 自动刷新列表。
- 安全：仅局域网；不端口映射；不云；PIN 与二维码同级；全屏不显示二维码。
- v1.1 扩展：`/api/channels`、`/api/play`、`/api/step`、`/api/volume`、`/api/fullscreen`、`/api/favorite`；本批不做，但 API/状态结构留好。

## 9. 开机自启 / 系统桌面

### 开机自启

- Manifest：`RECEIVE_BOOT_COMPLETED` + `BootSignalReceiver`（静态注册）。
- 信号适配器 `boot/BootActions`：通用（BOOT_COMPLETED、QUICKBOOT_POWERON、CONNECTIVITY_CHANGE、USER_PRESENT、MEDIA_MOUNTED、USB）+ 厂商候选（mediatek、com.tcl.*）；加厂商只改表。
- 策略表 `boot/BootActionPolicy`（1.0.43）：每个 action 带分类、拉起延迟、有效窗口、去重窗口；分类相同的 action 共享去重。
- 判定 `BootCoordinator`：开关（默认开）/ 用户主动退出 / 本 action 的有效窗口 / 同类 30 秒去重；窗口按 `SystemClock.elapsedRealtime()`（开机以来）算，不按进程启动时刻。
- 拉起：`BootLaunchPlan.DIRECT_LAUNCH=true` 时按策略延迟后直接 `launchNow`；`BootFrontCheckReceiver` 每 2 秒检查前台，被桌面盖住就 `REORDER_TO_FRONT` 带回，最多 12 次。
- 运行时信源/音频路由自检（1.0.47）：TCL legacy 上 `onStart` 立即查询 `TclSourceSwitch.isAndroidSource`，非 Android 时切回 `EN_TCL_STORAGE`，2.5 秒后重建引擎并重播当前台；运行中每 2 秒复查（10 秒冷却）。这是“App 重启几次后才有声”的直接修复：App 启动/回前台时信源可能被 TCL 留在 HDMI，音频轨 active 但扬声器无声。
- 开机音频自检（1.0.46）：`from_boot` + TCL legacy 首次播放会话，在 `BOOT_COMPLETED` 后 10 秒重新调用 `TclSourceSwitch.setAndroidSource`、强制重建引擎并重播当前台一次；`BOOT_COMPLETED` 没收到时开机 150 秒兜底。原因是 TCL 早期启动时 AudioTrack 可能 active 但音频路由/HAL 未就绪，表现为有画无声、多次开关机才恢复；只做一次，避免普通启动也重播。
- 策略基线（1.0.43）：

  | 分类 | 典型 action | 窗口 | 拉起延迟 | 说明 |
  |---|---|---|---|---|
  | BOOT | BOOT_COMPLETED / QUICKBOOT / 厂商 boot | 5 分钟 | 1 秒 | 可信开机信号，原行为 |
  | NETWORK | CONNECTIVITY_CHANGE | 5 分钟 | 6 秒 | 等 DHCP/DNS/路由稳定 |
  | USER | USER_PRESENT | 5 分钟 | 4 秒 | 等窗口/输入稳定 |
  | DEVICE | USB_DEVICE_ATTACHED / MEDIA_MOUNTED / MEDIA_SCANNER_FINISHED | 2 分钟 | 15 秒 | 只在开机早期算数，避免后来插 U 盘误拉起；USB/MEDIA 同类去重 |
- 等待桌面就绪那套（`BootWaitPlan` / `HomeResolver` / `BootAlarmReceiver`）保留，`DIRECT_LAUNCH=false` 可恢复。
- `from_boot` 首次起播延迟 3 秒；不重建 Activity、不改 Surface 绑定。
- 设置开关默认开；用户主动退出后本次开机不再拉起，下次重启清除。
- **TCL 实机**：
  - `system_server` 的 `AppWhiteListBama` 按 `/system/etc/appwhitelist_bama.xml` 清理非白名单应用；白名单未加/部分固件下 `BOOT_COMPLETED` 不投递给第三方。必须 root 把 `me.qnnp.tvlive` 加入白名单（remount rw；备份/恢复见设备 notes），OTA 可能覆盖。通用设备不需要改白名单。
  - 2026-10-29 实机（白名单已加）：`BOOT_COMPLETED` 实际约开机 95 秒送达；`CONNECTIVITY_CHANGE` 约 28 秒、`USB_DEVICE_ATTACHED` 约 25 秒。USB 是板载 USB WiFi 适配器上电枚举的副作用，只比网络早约 3 秒，不作为主信号。
  - 开机后信源可能停在 HDMI/HD（App 只是盖在上面，音频走 HDMI），`TclHomeHook` 优先反射 `com.tcl.tvmanager.TTvCommonManager.setInputSource(EnTCLInputSource.EN_TCL_STORAGE, true)` 切回 Android 应用层；反射失败（无权限/类不存在）再退回 `ENTER_HOME` 广播。`BootFrontCheckReceiver` 在 12 次前台确认内每次 bring 前补发，覆盖 `sourcemananger` 启动较慢的情况。
- 限制：现代 Android 后台启动 Activity 受限；TV 遥控器关机多为待机，待机唤醒通常不发 `BOOT_COMPLETED`。

#### 开机自启的分层（新增厂商只改表，不要往 BootLauncher 里塞分支）

| 层 | 位置 | 职责 | 扩展方式 |
|---|---|---|---|
| 信号表 | `boot/BootActions` | 哪些广播/action 能唤醒 App | 加一行 action → `BootActionPolicy` |
| 策略 | `boot/BootActionPolicy` | 分类/拉起延迟/有效窗口/去重窗口 | 改分类或时间常量 |
| 判定 | `boot/BootCoordinator` | 开关/用户退出/策略窗口/同类去重 | 不改 |
| 启动前动作 | `boot/BootHooks` + `BootLaunchHook` | 厂商特有的前置动作（TCL 切信源 `ENTER_HOME`）；返回 true 表示要延迟再拉起 | 新增 Hook 类并注册到 table |
| 拉起 | `boot/BootLauncher` | 按策略延迟发广播/排 alarm/startActivity | 不改 |
| 前台保活 | `boot/BootFrontCheckReceiver` | 每 2s 查 top，被桌面盖住就带回，最多 12 次 | 不改 |
| 可选等待 | `boot/BootWaitPlan` + `HomeResolver` | 等桌面就绪的旧链路，`DIRECT_LAUNCH=false` 时启用 | 不改 |
| 设备层 | TCL `/system/etc/appwhitelist_bama.xml` | 系统白名单，不在 App 代码里 | 见设备 notes |

- 禁止把厂商包名/action 直接写进 `BootLauncher` 或 `MainActivity`；一律走 `BootActions` / `BootHooks` 表。
- `BootHomeSwitch` 只作为 `TclHomeHook` 的实现细节，不直接被 Activity 调用。
- 设备相关的 root 改动（白名单、备份、恢复命令）只记在仓外设备 notes，不写进仓库。

#### 连续切台（画面态 CH+/−）

- 基准：从**焦点台**继续走，不是从播放台；这样连按 N 次就到第 N 个。
- 合并：550ms 内不切台，旧台继续播；每次按键把计时器往后推，松手 550ms 后才播最后落点。
- 落点回到原台：`same` 检查直接跳过，不动作。
- 焦点台/OSD 即时跟随，播放台/列表播放点等真正起播才更新。
- 导航里按 OK 选台：立即播，不合并。
- 首帧兜底：起播 2 秒无 `first frame` → 重配 VideoSurface（不销毁 player），最多 2 次。

### 系统桌面

- 主 APK 不声明 HOME。TCL PackageVerifier 会拒绝任何第三方 HOME（alias 与普通 activity 均失败），声明即整包装不上。
- 设置页提供「返回系统桌面」：显式拉起 `com.tcl.bama.launcher/.Launcher`；不存在时回系统 Home 选择器。
- 默认桌面留 v1.1 独立包（通用 Android TV），TCL 预计同样拒绝，不承诺。

## 13. 风险

- MT5882 可能只硬解 H.264；HEVC/AC-3 黑屏/无声；MediaPlayer 兜底不解决。
- TLS 1.0：https 源本机失败；通用版保留并提示。
- TCL PackageParser / PackageVerifier：无 banner；且拒绝任何第三方 HOME 声明（已用最小 APK 坐实），主 APK 永不带 HOME；每次出包仍要 TV 安装验证。
- 512/566MB：Exo 缓冲和台标内存；不加载 logo。
- 厂商自启白名单/现代 Android 后台限制：开机自启可能不生效；设置页提示。
- 64K 方法数：Exo+ZXing+Nano 需门禁。
- ExoPlayer 2.18.1 已 EOL；若 HLS 兼容问题再评估 Media3，不动 UI。
